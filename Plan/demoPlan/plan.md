# 第一人称数字人工厂实训改版计划

## 1. 改版目标与体验

基于现有台灯装配车间，改成约 25–30 分钟的第一人称实训：

**进入车间 → 与老师对话 → 接收任务 → 到工位观察与操作 → 完成客观题 → 老师反馈并布置下一项任务。**

已确认的设计：

- **键鼠自由行走**，老师在各教学站点等候。
- 老师采用**文字与语音结合**的方式讲解，按顺序布置任务。
- **全部客观题**，取消必填简答、长篇分析和人工评分。
- 答错可重答，分别记录**首次得分、掌握分和尝试次数**。
- 在现场选择两个工位，预览并确认交换。
- 沿用现有模型，完善近距离观察所需的碰撞、中文标识和灯光。

继续使用现有工艺、仿真参数和布局约束，不引入 VR、手工装配、老师步行寻路或新增产品。

## 2. 第一人称场景与交互

### 行走与界面

- 使用 `CharacterController` 实现移动：WASD 行走、鼠标转头、E 交互、Tab 查看任务、Esc 释放鼠标与打开暂停菜单。
- 默认视高约 1.65 米、移动速度 2 米/秒、视野角 65°；不加入跳跃、镜头摇晃和运动模糊，提供鼠标灵敏度调整。
- 行走时显示小准星、当前任务、目标方向，以及靠近对象后的交互提示。撤下现在常驻的大面积操作面板。
- 工位、老师和控制台在约 2 米内、视线无遮挡时可交互。
- 对话、答题、设置或确认交换时，停止行走、释放鼠标并暂停仿真；关闭后由学生明确继续。
- 墙体、工作台和货架阻挡玩家；装饰物不产生零碎碰撞。玩家不参与搬运车调度，行走不会改变仿真结果。

### 车间与老师

- 在入口设置接待点，在各工位旁设置观察点，在包装／成品区设置布局改善与总结教学点。
- 为工位增加面对学生的中文立牌、工序编号、当前状态，以及可点击的事件记录入口。
- 老师使用现有数字人模型，直接出现在车间中，保留待机、说话、口型和朝向学生的表现。
- 完成当前环节并确认前往下一站后，短暂淡出切换老师位置，并显示下一站方向；不让老师突然在对话中消失。
- 更换布局后，观察点和老师位置随工位更新，避开模型、墙体和学生所在位置。

### 现场交换工位

进入改善任务后，学生依次靠近两个作业工位并按 E 选择，界面显示原位置、目标位置和交换预览。

确认前必须暂停并重置当前订单；已完成的基准结果保留。供料区、成品区不能选择。若新位置会覆盖学生或老师，将角色移到提示过的安全观察点，再完成交换。

交换不改变工艺顺序、工时、人数或检验要求。

## 3. 老师带教与客观题设计

设置 **20 道题，每题 5 分，共 100 分**：10 道单选、6 道判断、4 道数字填空。现场观察和操作是推进条件，不额外计算主观分。

| 环节 | 老师布置的任务与现场活动 | 题目配置 |
|---|---|---|
| 1. 认识研究对象 | 在入口了解订单，到供料区确认研究对象、起终点与约束 | 2 单选＋1 判断 |
| 2. 认识工艺程序 | 到装配、紧固、检验与包装工位观察；查看组件汇入关系，区分加工与检查 | 3 单选＋1 判断 |
| 3. 记录产品流程 | 运行原始 20 件订单，跟踪 LAMP-01；查看加工、检查、搬运、等待、储存记录 | 2 单选＋1 判断＋1 填空 |
| 4. 用证据定位问题 | 完成原始订单，选取一条搬运和一条等待事件，用选择题学习 5W1H 分析 | 1 单选＋1 判断＋1 填空 |
| 5. 建立改善方案 | 在现场交换至少一对工位，判断 ECRS 类型，提交结构化运行预测 | 1 单选＋1 判断＋1 填空 |
| 6. 验证与总结 | 完成同参数的调整后订单，比较距离、等待和完成时间，判断结论是否成立 | 1 单选＋1 判断＋1 填空 |

四道填空分别使用：

1. LAMP-01 检验事件的实际持续时间。
2. 原始订单的累计产品载货距离。
3. 学生当前布局的单件完整载货路线距离。
4. 原始订单时间减去调整后订单时间，允许出现负数。

答案来自绑定的配置或已完成运行快照，不写死为参考改善布局结果。界面明确显示单位，允许整数或小数，数值误差容许 ±0.1。

### 任务与反馈规则

- 每次只展开一道题，完成后显示简短解析和对应现场证据。
- 首次提交记录首次分；答错后老师给提示，允许重答，正确后获得该题掌握分。使用提示的情况一并记录。
- 当前环节的必要观察、操作和纠错完成后，老师才布置下一环节。
- 可以自由走动和复习已完成内容，但不能跳过尚未完成的实验。
- 运行前预测改为对“距离、等待、完成时间”的趋势选择，不要求写文字，也不按预测是否命中扣分；预测随布局版本保存，开跑后锁定。
- 不要求学生找到唯一最优布局。结果变差也可完成学习，重点考查能否依据数据正确判断。
- 工艺程序图和流程程序图继续提供，以学生分类及实际事件组织展示。

### 对话与语音

- 每个环节具有固定的开场、任务说明、提示、纠错和收尾话术，确保离线也能完成课程。
- 提供“我准备好了”“再解释一下”“我该去哪里”“查看任务”等快捷回复，同时保留自由文字提问。
- 有可用接口时，支持语音识别、在线追问、老师朗读与口型；预设任务话术直接送入 TTS，不经大模型改写。
- 录音前停止老师当前朗读；开始／结束录音由学生控制，识别文本可见。
- 大模型负责解释，**不直接改分、跳关或交换工位**。任务推进以程序验证结果为准。
- 回答绑定当前课程、任务、布局和实验快照；离开对话、重置实验或切换任务后，过期回答不能覆盖新状态。接口失败时显示文字说明，学习流程继续可用。

## 4. 实现安排与兼容

按以下顺序实施，每一步形成可验证结果：

1. **第一人称基础**：加入玩家控制、碰撞、交互射线、精简界面和观察点，先完成“走到老师与工位旁交互”。
2. **老师带教流程**：加入“讲解→接任务→观察／操作→答题→反馈→下一站”的课程状态机，接入真实场景数字人。
3. **客观题改造**：建立 20 道题库、证据绑定、评分和重答机制，替换原有长文本表单与字数门槛。
4. **布局与语音联动**：实现现场双工位选择、预览、安全交换、预测锁定，以及预设讲解朗读和自由问答。
5. **存档、报告与交付**：完善恢复逻辑、完成验收、构建 Windows 程序并打开可见窗口。

必要的接口调整：

- 增加统一交互接口，供老师、工位和控制台提供提示与交互行为。
- 增加课程进度、题目定义与答题记录类型；记录任务 ID、题目 ID、证据快照、尝试、提示使用和两种分数。
- 在现有语音控制器增加可取消的“朗读指定教学文本”入口，复用已有 TTS、播放和口型链路。
- 第一人称控制与课程流程分离，不再由俯视镜头代码控制玩家相机。现有仿真内核与结果比较继续复用。

新课程使用独立的 v2 存档目录，不将旧版主观题草稿自动换算成新成绩。旧报告保留。恢复学习时回到安全教学检查点，未完成的订单重新运行，并明确提示。

新报告包含首次分、掌握分、尝试与提示记录、现场任务完成情况、实际证据、布局预测和结果比较，不再显示“主观 60 分待复核”。

## 5. 验收标准

- **行走与交互**：六个区域均可到达；不能穿过墙和工作台；文字输入时不会误移动；Esc 和窗口失焦后鼠标可正常释放。
- **老师带教**：从入口到总结完整走通；老师位置、任务提示和当前环节一致；重复交互不会重复发任务或计分。
- **题目与评分**：20 道题全部有解析；错答、提示、重答和存档恢复正确；不同布局的数字题根据实际证据判定。
- **现场实验**：可选取实际搬运／等待事件；交换后角色不会被模型覆盖；原始与调整结果不会混用。
- **仿真回归**：原始／参考布局仍分别得到单件 174／158 秒、20 件 1771／1454 秒；合法布局、数量守恒和同参数比较继续通过。
- **语音**：验证预设讲解、自由提问、打断、超时和离线继续；真实 ASR／TTS 验收与离线模拟结果分别记录，未验证项目明确列出。
- **画面与交付**：检查 1366×768、1920×1080、2560×1440 下的完整界面；进行实际行走、对话、答题和交换操作验收，不只检查自动生成截图。Windows 构建完成后打开可见窗口供直接试用。
